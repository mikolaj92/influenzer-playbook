# GitHub (witryna + discovery)

Kostium: warsztat. Gra: **konwersja README + velocity w oknie**. Nie git. Nie „ile gwiazdek łącznie”.

Trzy warstwy, jeden flywheel:

README zamienia ruch → stłoczona velocity gwiazdek → Trending (wzmacniacz) → wyższy baseline → kolejny release jako mniejsza fala.

Trending liczy **nowe gwiazdki w 24h/7d/30d**, nie total. Ten sam ruch rozlany na tydzień = nic. Stłoczony w 48h może wejść. Na Trendigu GitHub sam robi marketing (lepsza konwersja niż zimny social).

## Fala, wokół której gram

### Witryna (zawsze)
Repo *jest* stroną. About, topiki, LICENSE, social preview. README w jednym ekranie: one-liner → GIF → copy-paste quickstart, który działa za pierwszym razem. Zepsuty install = fałszywy launch. ~100 prawdziwych gwiazdek od ludzi, którzy nas znają, zanim publiczny spike (zero-star pada na „czy to w ogóle istnieje?”). Nie kupuję gwiazdek.

### Fala (launch)
Jedno okno 24–48h: Show HN + niszowy Reddit + PH jeśli pasuje + X. Tani auction najpierw (Trending języka), All Languages to nagroda. W spiku *siedzę na repo* (issue, Discussions). Jeden dzień na Trendigu to kampania.

### Między falami
Release = re-launch (watchers to już zbudowany kanał). Docs = SEO; README zostaje windą. Awesome listy i rejestry paczek to indeksy poza GitHubem. Scoreboard: install, wracające issue, contributorzy, gwiazdki/tydzień *po* spiku. Martwy projekt z 5k★ to przegrana.

## Nie

Proszę o gwiazdkę zamiast pokazać wartość. Launch i zniknięcie. Drip przez 5 dni. Show HN bez działającego dema. Fancy badge bez działającego quickstartu.
